        Como funciona a esteira

        Toda mudança no Tap Quiver faz o mesmo caminho até os clientes. Este painel mostra em que ponto ela está e qual botão apertar. Nada chega aos clientes sem a sua autorização.

        O painel se atualiza sozinho: a cada 5 segundos enquanto algo está andando (bolinha azul piscando no topo) e a cada 15 segundos quando está tudo parado. Não precisa clicar em Recarregar.

        O caminho de uma mudança

        1. No computador. Quem desenvolve altera o código neste PC. Você: nada a fazer.
        2. Em revisão (PR). A mudança é enviada ao GitHub como um pedido de mudança e os testes automáticos conferem se nada quebrou. Você: quando aparecer "testes ok", clique em Aceitar o PR.
        3. Testes e montagem. A mudança entra na versão oficial; a esteira testa de novo e monta a nova versão (cerca de 2 minutos). Você: só esperar.
        4. Sua autorização. A esteira para e espera você. Você: clique em Publicar no site, confira o que muda e confirme. Se não quiser agora, clique em Não publicar agora.
        5. No ar para clientes. Antes de trocar a versão, a esteira faz backup do banco de dados. Se algo der errado, ela volta sozinha para a versão anterior.

        As cores

        • Verde: tudo certo.
        • Azul: trabalhando; aguarde.
        • Amarelo: precisa de você.
        • Vermelho: problema; não publique e chame quem desenvolve.
        • Cinza: desligado ou sem informação.

        Os quatro cartões

        Código
        O código guardado no GitHub e os pedidos de mudança (PRs) esperando para entrar.
        Ambiente de testes
        Uma cópia do sistema que roda neste PC para testar antes dos clientes. Ligar ou desligar não afeta o site.
        Esteira
        A linha automática que testa, monta e publica. Sempre pede sua autorização antes de publicar.
        Site dos clientes
        O sistema que os clientes usam, no servidor da Hostinger: se está no ar, qual versão, backup, o uso de CPU, memória e disco do servidor (com o gráfico da última hora) e a saúde de cada contêiner. Embaixo, os backups do banco guardados no servidor, com a opção de baixar para a pasta Downloads ou apagar (digitando o nome do arquivo; o mais recente nunca pode ser apagado).

        Palavras que aparecem

        GitHub
        O site onde o código fica guardado, com o histórico de todas as mudanças.
        PR (pull request)
        Um pedido para juntar uma mudança à versão oficial. Vem com testes automáticos.
        Aceitar (merge)
        Juntar o PR à versão oficial. Ainda não publica nada.
        Atualizar o PR
        Quando o PR foi feito sobre uma versão oficial antiga, ele precisa trazer as últimas mudanças antes de ser aceito. Os testes rodam de novo e depois aparece o botão Aceitar.
        Esteira por dentro
        O desenho abaixo do caminho: as etapas da esteira (preparar, testes, montagem, publicação), com tempo e situação de cada uma.
        Versão oficial (main)
        O código aprovado, de onde saem as publicações.
        Testes automáticos (CI)
        Verificações que rodam sozinhas a cada mudança. "Testes ok" significa que nada conhecido quebrou.
        Publicar (deploy)
        Colocar uma versão no ar para os clientes.
        Contêiner (Docker)
        Cada peça do site roda isolada numa "caixa" no servidor: o sistema (API), o banco de dados, o Elasticsearch e o Kibana (logs) e o coletor que leva os logs até eles. Verde é saudável; se o sistema ou o banco ficar vermelho, o site é afetado.
        Produção (PRD)
        O site que os clientes usam. Ambiente de testes (DEV) é a cópia neste PC.
        Voltar versão (rollback)
        Publicar de novo uma versão anterior, quando a nova deu problema.
        Mudança no banco de dados (migration)
        Quando a versão nova altera a estrutura dos dados. A esteira ensaia numa cópia antes e faz backup.
        Versão (V855)
        Cada mudança aceita na versão oficial ganha o próximo número: V856 é a seguinte à V855. O código pequeno ao lado (ex.: 89e7d42) é o mesmo nome em formato técnico, usado pelo GitHub.
        Trazer a versão oficial
        Atualiza o ambiente de testes deste PC com a versão oficial mais recente, inclusive as mudanças no banco de testes. Não afeta o site.
        Copiar o banco do site
        Substitui o banco do ambiente de testes por uma cópia, feita na hora, do banco do site, para investigar problemas com os dados reais. O site não para; na cópia, e-mail e notificações ficam desligados. A cópia tem dados de clientes: não compartilhe.

        Regras de ouro

        1. Vermelho no topo: não publique; chame quem desenvolve.
        2. Não publicar agora é sempre seguro: o site continua como está.
        3. Voltar para uma versão anterior só se o site ficou com problema logo depois de uma publicação.
        4. Se o aviso de publicação mostrar mudanças no banco de dados e você tiver dúvida, pergunte antes de confirmar.
